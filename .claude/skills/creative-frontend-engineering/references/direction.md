# Direction and product architecture

**Brand scene.** For each reference name its specific contribution, such as a low horizon, an oblique crop, a type scale or the distribution of light. Translate one contribution into a testable composition. For a print studio the paper edge might supply the silhouette and a small edition number might establish scale. Test the silhouette in grayscale at thumbnail size. Reserve quiet space under text across narrow crops. Use proximity, proportion, alignment and contrast to keep the visual subject and its action connected. Reuse one recurring material, shape or phrasing to connect shots. Select an accent for meaning and check foregrounds against their actual backgrounds.

**Product flow.** Trace the short path from arrival to a meaningful result, including the way back. Group information in the order the person needs it to decide. Define empty, loading, success, stale, unavailable and recoverable-error states only where the operation can enter them. Put validation by its cause. Preserve the user's entered values across retries. Use semantic roles and native interactions for the primary flow. When a narrow viewport rearranges a screen, keep reading order, actions and current context intact.

**Component boundary.** Separate a durable domain value (selected edition), a transient input (pointer position), and a derived view (visible result list). Give each value one owner. Model the interactive part in terms of events and allowed transitions. Derive ARIA state and visible labels from the same source. Keep palette and type primitives separate from semantic roles such as action, warning and focus. Make busy, focus-visible, pressed and disabled states distinguishable without color alone.

**Rendering decision.** Static content with build-time inputs can be delivered as SSG. Personal or frequently changing initial content often belongs in SSR. Stream independent slow regions when their placeholders reserve layout and the reading order remains useful. Hydrate only genuinely interactive regions; initial client output must agree with the server on IDs, locale, data and visible state. CSR suits a tool behind authentication when first-load cost is acceptable. Keep secrets on the server. Test one deep link, a delayed response and keyboard navigation before adding another layer.

**Measurement.** First render real content using local assets and the project's established stack. Inspect the largest paint candidate, layout shifts and main-thread work during input. Keep animation ticks outside component-tree updates where possible. Compare production builds on the same viewport, browser and CPU conditions. Attribute improvements to a measured bottleneck.
