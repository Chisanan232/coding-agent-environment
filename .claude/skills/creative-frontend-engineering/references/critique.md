# Rendered critique

Start with the task a viewer should finish and the visual reference's most important element. Capture matched viewport, device scale, data, font readiness, seed, interaction sequence and elapsed time. Keep personal material and raw captures local. A design comparison needs matched content and budgets, a known generator, and a reviewer who can identify their relationship to it.

- **Composition and type.** Inspect the first viewport, thumbnail and narrow crop. Name what draws attention first and which action follows. Check line breaks, margins and the relation between text and imagery. Record an observable defect such as an action separated from its subject at 375 px.
- **Motion.** Record before, middle and settled states. For a loop include consecutive frames across the seam. Compare displacement across the seam with an ordinary adjacent-frame step; an identical first and last pose can still conceal a velocity jump. For interruptible transitions, reverse during motion and verify continuity and terminal state. A still alone cannot prove this.
- **Input and accessibility.** Exercise a pointer, keyboard and a touch path where supported, including cancellation. Inspect focus return, accessible names, key order and the visible static or reduced-motion end state. Use a real device or a second engine when the claim concerns that environment. Record emulation as emulation.
- **Performance.** Measure frame intervals during a specified interaction and disclose sample count, browser, resolution, software rendering and headless mode. Separate execution timing from tool startup and model generation. Document large spikes and layout shifts. Compare like hardware and capture settings.
- **Refinement.** Give each important observation a location and the expected user outcome. Choose one repair, rerender the same states and identify which differences remain. Keep manual artistic judgment separate from measured deltas and automated pass conditions.

## Perceptual improvement claims

Before the comparison, name each claimed cue, its location, the gesture and the interval when a viewer should see it. Match original and candidate with the same camera, framing, viewport, seed, input path and timing. Include idle, contact and release if claimed. Play the full frame at normal viewing scale and 1× speed on representative desktop and touch viewports. Keep input traces, captions, zoom and differences off this first pass. Give the independent reviewer neutral arm labels and ask what changed, where and when, before revealing the expected answer. Record whether the reviewer actually watched continuous playback or inspected sampled frames.

Record separate findings for **implementation** (which path ran), **function** (input and outcome), **numerics** (units, limits and measured trajectory), **perception** (unaided observation in each full-size clip) and **art direction** (coherence, hierarchy, regressions and owner judgment). For each claim cite the clip, viewport and timestamp, observed cue and adverse changes. Use close-ups, slowed playback and layer ablations to explain a result after the ordinary-view pass. Pixel differences can disprove identical output; they cannot decide beauty or visibility.

If only the trace or diagnostic crop reveals the change and ordinary playback was assessed, record **implemented, perceptually negligible** for that view. If matched playback or capable observation is missing, record **perception unverified**. A conflicting owner review remains visible and governs product acceptance. Neither outcome supports a claim of meaningful artistic improvement.
