# Retire the broad `Bash(rtk proxy *)` ask (SPE-119, owner-run)

Status tokens, kept separate: `POLICY_VERSION_CONTROLLED` (this PR), `POLICY_MERGED`, `POLICY_DEPLOYED` (applied to `~/.claude/settings.json`), `POLICY_LIVE_TESTED` (the matrix below passes on the deployed file). Nothing here is deployed by merging. This does **not** fix the PR-merge classifier problem; that is SPE-118.

## Root cause

`~/.claude/settings.json` has `permissions.ask: ["Bash(rtk proxy *)", ...]` and no `rtk proxy` allow. Rules are evaluated deny, then ask, then allow, so an ask cannot be neutralized by a narrower allow. The rtk hook rewrites `git diff` to `rtk git diff` (which the existing allows match) but **never** rewrites `rtk proxy ...`, so any command the agent types with that prefix hits the broad ask. Measured on the live settings with the real host (`claude -p`, auto mode, a `PermissionRequest` logger that records, never answers, each prompt): **8 of 8 routine commands prompted**, including the env-prefixed and piped forms. Settings sources checked: user (`~/.claude/settings.json`, `settings.local.json`), project (`.claude/settings*.json`), managed (none present). Only the user file carries the rule; there is no `deny`.

Removing the ask alone is unsafe: measured earlier (SPE-114), force push, IAM and secret reads through the wrapper then execute because nothing asks for them. The replacement therefore ships the scoped asks first.

## What changes (exact)

Generated by `scripts/workstation-policy.py render-settings --kind personal --proxy-scoped`, committed as `docs/examples/candidate-settings-rtk-proxy-scoped.example.json`:

| Bucket | Change |
|---|---|
| `permissions.ask` | **retire** `Bash(rtk proxy *)` (the only ask the tool may retire); **add** the 31 scoped `rtk proxy` asks from PR #93, the wrapped parity asks `rtk proxy git*--ou*`, `*--ext*`, `*--tex*`, `*--no-index*`, `rtk proxy git fetch*--upl*` (git accepts any unique prefix of a long option, so the prefixes are the shortest unambiguous ones), `rtk proxy gh pr merge*`, and a wrapped twin of **every** bare protected ask (`rtk proxy gh release create`, `cargo publish`, `npm publish`, force push, delete, and the rest of `ASK_BASH_RULES`), so wrapping never lowers a protection, and the four bare/`rtk` `gh api -X/--method DELETE` forms |
| `permissions.allow` | **add** 26 scoped rules: `rtk proxy git {diff,show,log,status,rev-parse,rev-list,ls-files,merge-base,ls-tree,describe,blame}:*`, `rtk proxy grep:*`, `rtk proxy cargo {test,build,check,clippy,fmt}:*`, `rtk proxy cargo nextest run:*`, and the bare and `rtk` spellings of `git {ls-tree,merge-base,describe,blame}:*` (`git ls-tree` was denied about 20 times in 30 days of real sessions with no allow). `git cat-file` is left out because `--textconv`/`--filters` run helpers |
| everything else | untouched (`deny`, `env`, `autoMode`, hooks, other keys) |

Not added: `Bash(rtk proxy *)` or any broad wrapper allow, a blanket `Bash(*)`, any `deny` change. `candidate-rollout.py` refuses (BLOCKING) any candidate allow that is not exactly one of the 26 scoped rules, and the candidate lint rejects broad wrapper and blanket allows. The post-merge check also blocks if any protected wrapped command, including every parity flag form, would stop asking. Protected operations (force push and remote branch delete, release and publish forms, terraform apply/destroy, IAM and secret access, kill, shell re-entry, absolute-path exec, worktree removal) keep asking in every wrapped spelling.

## Measured on the real host

Fixture repository, `claude -p --permission-mode auto`, candidate = live copy plus the change above, 24 commands:

| Group | Live now | After |
|---|---|---|
| Routine wrapped commands (8: cargo with env prefix and pipe, git diff with paths, git show piped to sed then rtk grep, grep piped to grep/cut/head, git log, git status, cargo version, env-prefixed git diff) | **8 prompts** | **0 prompts** (7 executed, 1 reported with different wording but ran with no permission request) |
| Protected wrapped commands (16: `--output`, `--ext-diff`, `--no-index`, `--upload-pack`, force push, global-option push, env-prefixed push, chained push, `sh -c`, gcloud, terraform apply, API delete, worktree remove, absolute path, env-prefixed gcloud, reset --hard) | n/a | **16 of 16 prompt** |

The measured candidate also carried an `rtk proxy rg:*` allow that was removed afterwards (see below); none of the 24 commands used `rg`, so the counts stand. Evidence files stay in the private QA directory (`cases-p0.json`, `friction-p0-*.json`). Limits: one host, one Claude Code version; headless auto mode; the matcher's glob rules are not published, so every pattern here was measured, not assumed.

**Residual a user setting cannot control:** a wrapped command that matches neither an ask nor an allow (for example `rtk proxy python3 -c ...` or `rtk proxy sh -c ...` payloads that avoid the named rules) goes to the Auto Mode classifier, whose verdict is non-deterministic and not configurable beyond `autoMode` text. Routine work stays on named allows; unusual wrappers may still be judged by the classifier.

Allowed-verb exposure, stated plainly: `rtk proxy cargo {test,build,check,clippy,fmt}` can run build scripts, test code and `--config` helpers, exactly like the bare `cargo test/build/clippy/fmt *` and `rtk cargo ...` allows already in the live file; the wrapped forms add no capability beyond that parity. `nextest` is allowed only as `nextest run` (the bare allow is the same), so `nextest self update` is not covered. `git diff/show/log --textconv` can run a configured driver; it asks in the wrapped form, while the bare `git diff:*` allow already in the live file does not ask for it (an existing exposure this change does not widen). `rg` is deliberately not allowed because `rg --pre CMD` runs CMD and no bare rg allow exists; `rtk proxy rg` stays with the classifier.

Also: agents should prefer the plain command (`git diff`, `cargo test`) because the hook rewrites it to a rule-matched `rtk` form; `rtk proxy` is only for deliberately unfiltered output.

## Order matters: canary first, then this candidate

The measured configuration is the asks-only canary (`docs/examples/candidate-settings-personal-asks-only.example.json`, approved in principle, see `docs/ROLLOUT-PERSONAL-MAC.md`) **plus** this candidate. Apply the canary first: it carries the bare release, publish, remote-branch-delete and `--admin` asks. This candidate retires the broad wrapper ask, and without the canary the bare forms would be left to the non-deterministic classifier (measured: a remote branch delete ran unprompted on the current live file). Run the procedure below once per candidate, in that order, each with its own plan and hashes.

## Owner apply (one procedure per candidate, hash-pinned, with backup)

The agent does not edit `~/.claude/settings.json`; earlier host denials of that edit stand. Run from a clean checkout of `main` after this PR merges (`R` = checkout, `L` = live file):

```bash
R=~/Bryant-Developments/coding-agent-environment; L=~/.claude/settings.json
C=$R/docs/examples/candidate-settings-rtk-proxy-scoped.example.json
python3 $R/scripts/candidate-rollout.py plan --live "$L" --candidate "$C"      # read-only; prints live_sha, result_sha, report
```

Go only if the plan shows `"blocking": false`, `asks_retired` is exactly `["Bash(rtk proxy *)"]`, `retire_refused` is empty, `allow_added` has 26 rules and no ask other than that one is missing from the result. Then, with the two hashes from the plan:

```bash
python3 $R/scripts/candidate-rollout.py apply --live "$L" --candidate "$C" --expect-live-sha <live_sha> --expect-result-sha <result_sha>
python3 $R/scripts/candidate-rollout.py verify --live "$L" --expect-result-sha <result_sha>     # VERIFIED
```

`apply` writes a 0600 backup `~/.claude/backups/settings.<live_sha12>.json`, refuses if the file changed since `plan`, and replaces the file atomically. Alternative through the supported UI: in a session run `/permissions`, delete the `Bash(rtk proxy *)` entry from the Ask tab, then add the 26 allow rules and the missing asks from the candidate file by hand; the CLI route is preferred because it is hash-checked.

### Verify the effective result

1. New session: `/permissions` shows no `Bash(rtk proxy *)` under Ask, the 26 scoped allows, and the scoped asks.
2. Run the four everyday shapes (a piped `rtk proxy cargo test`, `rtk proxy git diff origin/main...HEAD -- tests/ docs/`, `rtk proxy git show ... | sed`, `rtk proxy grep -rn ... | grep | cut | head`): no prompt.
3. Run `rtk proxy git push --force origin <your-own-branch>` against a throwaway branch only, or read the prompt and decline: it must prompt.
4. Existing and resumed sessions: the documentation does not state when a running session reloads permission rules, so treat them as unchanged and start a new session; after `--resume`, check `/permissions` before relying on the new rules.

### Rollback (hash-pinned)

```bash
python3 $R/scripts/candidate-rollout.py rollback --live "$L" --backup ~/.claude/backups/settings.<live_sha12>.json \
  --expect-backup-sha <live_sha> --expect-live-sha <result_sha>
```

It refuses if the live file is not the applied result (so later edits are not silently lost) or if the backup hash differs.
